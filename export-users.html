KV → D1: экспорт users.sql

Страница читает namespace USERS через Cloudflare API и собирает SQL-файл для D1. Ничего не изменяет в KV. Токену достаточно права Workers KV Storage: Read.

Экспорт через воркер — рабочий способ

Воркер сам читает KV и отдаёт готовый SQL. Токены Cloudflare не нужны, только адрес воркера и ADMIN_TOKEN.

Перезаписывать существующие записи в D1
Режим ниже (напрямую Cloudflare API) в браузере не работает: api.cloudflare.com не отдаёт CORS-заголовки, поэтому любой fetch падает с «Failed to fetch». Оставлен для справки.
Использую Global API Key (email + ключ) вместо токена
Перезаписывать существующие записи в D1 (иначе пропускать)
После импорта не удаляйте данные из KV минимум 1–2 недели: это резервная копия на случай отката.
Global API Key даёт полный доступ ко всему аккаунту и не ограничивается чтением. Используйте его только локально, не на публичном сайте, и после экспорта выполните Roll в My Profile → API Tokens (это сменит ключ для всех интеграций) либо перейдите на scoped-токен.
