# Переезд пользователей из KV в D1 (без Node.js)

Всё делается в браузере. Нужны только Cloudflare Dashboard и файлы из этого пакета.

## 0. Подготовка (5 минут)

1. **D1 → база `wrangler_d1` → Console** → вставить целиком `users_schema.sql` → **Run**.
   Проверка: `SELECT COUNT(*) FROM users;` → должно быть `0`.
2. **My Profile → API Tokens → Create Token**:
   - Permissions: `Account` → `Workers KV Storage` → **Read**;
   - Account Resources: ваш аккаунт.
   Скопировать токен. Больше прав не нужно.

## 1. Экспорт из KV

1. Открыть `export-users.html` (локально в браузере телефона — просто файл, сервер не нужен).
2. Заполнить:
   - **Account ID** — на главной Cloudflare Dashboard, в правой колонке;
   - **KV Namespace ID** — Storage & Databases → KV → `USERS` → значение ID
     (в старом `wrangler.toml` это `23d60800f794435b8596c28c62de177c`);
   - **API Token** — из шага 0;
   - Префикс: `user:`.
3. **Проверить доступ** — покажет, сколько ключей видит.
4. **Экспортировать users.sql** — скачается файл.
   - Чекбокс «Перезаписывать существующие»: при первом импорте не важен,
     при повторном включает `DO UPDATE` вместо `DO NOTHING`.

Страница только читает KV. Ничего не пишет и не удаляет.

> Если агрегированный endpoint Cloudflare недоступен, страница сама переключится
> на поштучное чтение metadata (медленнее, но работает так же).

## 2. Импорт в D1

**D1 → база `wrangler_d1` → Console** → вставить содержимое `users.sql` целиком → **Run**.

Файл обёрнут в `BEGIN TRANSACTION; ... COMMIT;` — либо применится всё, либо ничего.

## 3. Проверка

```sql
SELECT COUNT(*) AS total FROM users;
SELECT COUNT(*) AS with_region FROM users WHERE oblast_key IS NOT NULL;
SELECT COUNT(*) AS notifying FROM users WHERE notify = 1;
SELECT chat_id, lang, oblast_key, last_alert_state FROM users LIMIT 5;
```

`total` должно совпасть с числом, которое показала страница экспорта.
Если не совпало — **не удаляйте KV**, сначала разберитесь.

## 4. Что дальше

Данные в D1 уже лежат, но текущий `worker.js` из этого пакета **продолжает
работать с KV** — это сделано намеренно, чтобы обновление кода и миграция данных
не ломали друг друга.

Порядок безопасного переключения:

1. Залить `worker.js` с исправлениями (он ещё на KV) → проверить, что бот жив.
2. Погонять экспорт ещё раз, чтобы забрать свежие изменения (или просто
   переимпортировать `users.sql` с чекбоксом «перезаписывать»).
3. Затем переключить код на D1: `readUser`/`writeUser`/`notifyUsers`/`collectUsers`
   начинают читать и писать таблицу `users`, а KV остаётся только для `device:*`.
   Этот патч — отдельный шаг, могу подготовить.

## 5. Откат

Пока KV не тронут — откат бесплатный: вернуть старый `worker.js`, KV-данные на месте.
Поэтому не удаляйте `user:*` из KV, пока сервис не проживёт на D1 хотя бы неделю.

## 6. Гигиена

- Удалить API-токен после экспорта: My Profile → API Tokens → Delete.
- Не хранить токен в закладках и скриншотах.
- При деплое через GitHub: `users.sql` и `.dev.vars` не коммитить — они в `.gitignore`.
  `wrangler.toml` уже содержит ваши реальные ID, так что push можно делать сразу.
