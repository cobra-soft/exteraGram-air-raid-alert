# Что изменено в worker.js (патч 2026-10-23)

Изменения только в `worker.js`, `wrangler.toml`; API и формат ответов для плагина не менялись.
Версия по-прежнему `air-raid-panel-2026-10-01` — при желании поднимите `WORKER_VERSION`.

## 1. `/setup-webhook` и `/webhook-info` больше не открыты без `ADMIN_TOKEN`

Было: если секрет `ADMIN_TOKEN` не задан, оба эндпоинта отвечали любому
(`adminGate` требовал наличие токена, а не его проверку). Любой мог дёргать
`setWebhook` с `drop_pending_updates=true` и обнулять очередь уведомлений.

Стало:

```js
const restricted = url.pathname === "/setup-webhook" || url.pathname === "/webhook-info";
if (restricted) {
  if (!env.ADMIN_TOKEN) return json({ ok: false, error: "ADMIN_TOKEN secret is not set; ..." }, 403);
  if (!(await isAdmin(request, env))) return new Response("Unauthorized. Log in at /admin", { status: 401 });
}
```

Заодно убрана подсказка про `/admin?token=...` — такой параметр код никогда не поддерживал.

## 2. `/start <deviceId>` не перетирает чужую привязку

Было: любой Telegram-пользователь мог отправить `/start чужой-device-id-ru` и
переписать `device:<id>` на свой чат.

Стало: device_id валидируется (`^[a-zA-Z0-9-]{1,64}$`, как в `/telegram/get-chat-id`),
и существующая привязка к другому чату не перезаписывается — только лог-предупреждение.

## 3. Экранирование названия региона

`region_name` приходит от клиента и подставляется в сообщения с `parse_mode: "HTML"`.
Символы `<`, `&` в названии давали 400 от Telegram, а из-за механики dedupe
пользователь навсегда переставал получать уведомления.

Стало: `escapeHtml()` применяется в `stateMessage()`, `deliverChange()` и при отправке
`subscribed`; `region_name` обрезается до 80 символов при регистрации.

## 4. Permanent-ошибки отправки больше не «замораживают» состояние

Было: при 400/403/404 от Telegram сообщение не ретраилось, но
`user.last_alert_state` всё равно обновлялся — пользователь молча терял все
будущие уведомления об этом состоянии.

Стало: claim снимается, состояние не сохраняется, ошибка попадает в общее окно
ретраев (до 5 минут), а не теряется молча. Если и после этого не вышло —
следующая смена тревоги снова запустит отправку.

## 5. Защита KV-metadata (лимит 1024 байта)

Было: `writeUser` писал объект как metadata без ограничений. При длинных
`first_name`/`region_name` запись падала, и состояние пользователя расходилось с сервером.

Стало: `shrinkUserMetadata()` перед записью: сначала чистит telegram-поля,
затем укорачивает `region_name`, затем oldest-поля. Имена из Telegram обрезаются до 64 символов.

## 6. Валидация локации в `/register`

`oblast_key`/`district_key` теперь обязаны существовать в словарях
`OBLAST_NAMES_UK` / `DISTRICT_NAMES_UK`, `district_key` без `oblast_key` отклоняется.
Раньше можно было записать произвольную строку и получить «вечный clear».

## Что НЕ вошло в патч (следующие шаги)

- Переключение `user:*` на таблицу D1 (данные уже готовы, см. `MIGRATION.md`).
- Nonce/отзыв админ-сессии: HMAC по-прежнему только от `exp`, cookie живёт 7 дней.
- Полноценный rate limit на `/register` и `/telegram/get-chat-id` — лучше
  настраивать на уровне Cloudflare WAF, а не в коде воркера.
